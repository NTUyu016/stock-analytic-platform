## 待決事項 3：評分與建議（已定調五級，以下是殘留子問題）

### 3.1 已知事實

**（a）舊 skill 的合成鏈（實讀確認，L1833–1873）**

```
final_score = Σ(維度分數 × 正規化權重)          L1833
recommendation = BUY (>0.33) / SELL (<-0.33) / HOLD   L1836–1841
confidence = abs(final_score)                   L1843
confidence *= (1 + earnings_timing.adjustment)  L1847   （盤前 14 天 → ×0.7）
若 RSI>70 且近 52 週高 → BUY 降 HOLD、confidence ×= 0.7   L1860–1863
若 risk-off → BUY 的 confidence ×= 0.7          L1866–1868
若 geopolitical → BUY 的 confidence ×= (1-penalty)     L1871–1873
```

三個必須攤在桌上的性質：

1. **`confidence` 不是獨立資訊，它就是 `final_score` 的絕對值**（L1843）。本次實測 `2330.TW` 的 `final_score` 與 `confidence` 都是 `0.4269230769230769`——**同一個數字印兩次**。畫面若把「級距」與「信心度」並列，使用者會以為是兩個維度的資訊。
2. **所有折扣只作用在 `confidence`，且只作用在 `BUY`**（L1867、L1872 的 `if recommendation == "BUY"`）。SELL 從不被折扣。這個不對稱在五級化之後會放大（strong sell 也不折扣？）。
3. **`recommendation` 會被覆寫但 `final_score` 不會**（L1852、L1857、L1862）。即畫面上可能出現「分數 0.45 但顯示 HOLD」，而**沒有任何欄位記錄它被降級過**——降級理由只出現在 `caveats` 的自由文字裡。

**（b）「附上依據」在資料結構上還缺什麼**（L1957–2047 實讀）

`components_dict` 已經保留了每一維的**原始分數**與**原始數值**（如 `earnings_surprise.surprise_pct`、`fundamentals.pe_ratio`、`momentum.rsi_14d`）。這對使用者要求的「展開看依據」是好消息。但：

> **正規化後的權重（L1830 的 `normalized_weights`）與每一維的加權貢獻（L1833 的乘積）算完即丟，沒有進入 `components_dict`。**

要呈現「這一維貢獻了多少分」——這正是 issue #14 留言要求的——**必須新增中間結果的保留**。`tech-stack.md` §5 也已預告 `synthesize_signal`（約 300 行）「評分權重全部重新取捨」。

**（c）五級的標籤與 yfinance 分析師共識評等字面完全相同**

L535–541 的 `rec_scores` 就是 `{strong_buy: 1.0, buy: 0.7, hold: 0.0, sell: -0.7, strong_sell: -1.0}`——**使用者選的五級，字面上與 yfinance `recommendationKey` 的取值一模一樣**。本次實測 `2330.TW` 的分析師共識輸出為 `"consensus_rating": "Strong Buy"`。

→ 若分析頁同時顯示「本站評等」與「分析師共識」，畫面上會出現兩個 `Strong Buy`，一個是本站算的、一個是外部 35 位分析師的，而**分析師共識本身又是本站評等的輸入之一（權重 0.20）**。這是語意混淆與循環引用外觀的風險。

**（g）官方 OpenAPI 只有最新快照**（#3 §3.1、§3.3、§0）——「今天不抓，明天就沒有」。這使「盤後排程」不只是效能選擇，而是**資料保存的前提**。

### 5.2 選項盤點

| 選項 | 代價 | 風險 |
|---|---|---|
| **A. 每次開頁即時算，不快取** | 零基礎設施 | 實測 7–25 秒／檔，而 `api` scale-to-zero 冷啟動還要疊加；yfinance 速率限制未公告會 429（#3 §1）；重整頁面就再打一輪外部 API |
| **B. 開頁算 ＋ 行程內短 TTL** | 幾行程式 | **scale-to-zero 使其近乎無效**（見 (c)）；且對同一使用者的第二次開頁才有用 |
| **C. 落地快取表（分析結果存 DB，帶 `computed_at`）** | 新增一張表 → 要回寫 `data-model.md`；要定 TTL 與失效規則 | 若寫成「事實來源」而非「快取」，會重蹈 `portfolio_snapshot` 被否決的理由（修正輸入後不會自動修正結果）。**必須明確標成快取，且能一鍵重算** |
| **D. 盤後預先算全部持股標的** | 需要排程執行器（**屬 #17，未定**） | 只涵蓋持股標的；**使用者查詢非持股標的時沒有預算結果**，仍需 A 的路徑。等於兩條路徑都要寫 |
| **E. 混合：慢維度盤後預算 ＋ 價格類即時算** | 兩層合成，要定義「哪些維度屬慢」 | 合成時兩層的 `as_of` 時間不同 → **畫面上必須說得清楚「這個結論是用什麼時點的資料算的」**，否則會出現「RSI 是今天的、財報是上季的、法人是昨天的」卻只標一個時間 |

**「做錯日後會很痛」**：
1. **時間戳的顆粒度。** 若只存一個 `computed_at`，日後要做 E（混合）就得改綱要。若每維各自帶 `as_of`，一開始成本很低。這與 `dashboard-ui.md` §3「兩種降級都必須同時做兩件事」是同一個精神——**使用者必須知道自己在看什麼時點的東西**。
2. **官方資料只有最新快照**（(g)）。**每晚不存，就永遠補不回來，且合法的回補路徑只有 FinMind（授權未明）。** 這條讓「盤後排程」的時間壓力與「分析頁效能」無關——即使 v1 決定即時算，資料落地的排程可能仍然該現在就做。
3. **快取失效的觸發條件。** 使用者新增一筆 Transaction 不會改變分析結果（分析看的是市場資料不是持股），但**新增一支標的會**。若快取鍵只有 `instrument_id`，這點無礙；若混進了 Position 相關資訊就會失效混亂。

1. **yfinance 的實際速率上限**——#3 §1 記「未公告，Yahoo 端會 429」，**未能查證，需人工確認**。這直接決定 A 選項是否可行。
2. **本次 25.3s → 7.3s 的差異來源**（Yahoo 端快取？DNS？uv 環境冷啟動？）——**未能查證**。故不可把 7.3s 當成穩態值，也不可把 25.3s 當成上限。
3. **`api` 從 scale-to-zero 冷啟動的實際延遲**——屬 #17，**未能查證**。
4. **多檔並行分析時 yfinance 是否會被限流**——本次只測單檔，**未測**。

## 待決事項 6：呈現形式（文字結論／雷達圖／分數卡）

### 6.1 已知事實

1. **圖表庫已選定且分工明確**：`recharts` 負責「統計圖：資產配置圓餅、貢獻度長條、**雷達／分數卡**」；`lightweight-charts` 只做金融時間序列，「圓餅和雷達它不做」（`tech-stack.md` §6）。→ 雷達圖與分數卡在技術上已備妥，不需新增相依。
2. **`lightweight-charts` 強制 attribution 不可關閉**（`tech-stack.md` §6）——若分析頁放 K 線，TradingView 標示必須留著。
3. **顏色是硬約束**（`dashboard-ui.md` §2）：
   - 紅綠只給價格方向 → **分數卡不可用紅綠表示好壞**，雷達圖的填色也不行。
   - 互動元素一律墨色，**沒有彩色 accent**。
   - 類別色在淺色模式對比 <3:1 → **每一段都必須有可見的直接標籤，不可只靠 hover**。→ 若雷達圖的八個軸靠顏色區分，這條會被撞到。
4. **版面語彙已定**（`dashboard-ui.md` §1、§5）：卡片吃同一組 `--pad` / `--hd-h`；並排列表用同一種列結構；數字欄一律 `tabular-nums` 右對齊。
5. **使用者對「太分散又資訊不清楚」的原始評語**（`dashboard-ui.md` §1）：解法是「**把面板改少改大**」而非搬動位置。→ 八個維度若各自一張小卡，方向與這條相反。
6. **使用者要求可展開看依據**（issue #14 留言）。而 `components_dict`（L1957–2047）已備好每維的原始數值，但**缺加權貢獻**（見待決 3 §3.1(b)）。
7. **「永遠亮著等於沒有」原則**（`dashboard-ui.md` §3；#19 對帳只比股數的同型理由）——若每檔股票都掛三條 caveat，caveat 會被學會忽略。本次實測 `00878.TW` 的四條 caveats 中有兩條是無關的美國學區新聞。
8. **手機是堆疊單欄**，且使用者對此版面在手機上的評價**高於桌面**（`dashboard-ui.md` §1）。
9. **issue #14 自己寫了「可能需要一張原型票」**；#11 的先例是原型跑了**五輪回饋**才選定變體 D。

### 6.2 選項盤點

| 選項 | 優點 | 代價／風險 |
|---|---|---|

## 建議的提問順序

### 依賴關係（先看形狀）

```
        ┌─ Q0 前提：分析頁要回答什麼問題？實際持股組成？（未查證，必須先問人）
        │
        ├─ Q1 待決 4（美股共用與否）──┐
        │                              ├─▶ Q2 待決 1（維度取捨）
        │  Q1' 待決 3 的隱藏前置：     ─┘   （維度集合要不要跨市場成立、
        │      「維度不足時給不給級距」       ETF 路徑要不要獨立）
        │                                        │
        │                                        ▼
        │                              Q3 待決 2（資料來源與更新頻率）
        │                                 ⚠️ 必須當場解掉 #4 與 #3 對 /rwd/ 的衝突
        │                                        │
        │                                        ▼
        │                              Q4 待決 5（運算時機與快取）
        │                                 ⚠️ 部分答案屬 #17，本票只能定分工
        │                                        │
        │                                        ▼
        │                              Q5 待決 3 剩餘（門檻、信心度、依據呈現）
        │                                        │
        │                                        ▼
        └─────────────────────────────▶ Q6 待決 6（呈現形式，可能開原型票）
```

### 逐題理由

| 順位 | 問什麼 | 為什麼在這個位置 |
|---|---|---|
| **Q0** | 分析頁要回答使用者的哪個問題（「該不該買」vs「這支發生什麼事」）？以及**實際持股組成**（幾檔上市／上櫃／ETF／美股） | 這是**唯一一個查不到、只能問人**的前提，而它同時決定 ETF 路徑、上櫃平行實作、美股路徑三件事要不要做。先問它可以直接砍掉後面一整批選項 |
| **Q1** | 待決 **4**（美股沿用八維 vs 共用簡化維度 vs 依市場宣告） | **排在維度取捨之前**，因為它決定「維度集合是否必須跨市場成立」。若先定了台股八維再問美股，答案只剩「複製一份」或「砍掉美股」兩種，而選項 C（共用框架、能力宣告）會在那時已經沒得選 |
| **Q1'** | 待決 3 的隱藏前置：**維度資料不足時，還給不給五級結論？** | 表面屬待決 3，實際是**維度取捨的約束**：若堅持「每檔標的都要有級距」，就不能把只在大型股有覆蓋的維度（分析師、財報意外）放成主幹。實測 `00878.TW` 只有 4 維、confidence 0.036 卻照樣顯示 `HOLD`，就是這個問題的具體樣貌 |
| **Q2** | 待決 **1**（v1 放幾維、哪幾維） | 有了 Q0/Q1/Q1' 才有取捨基準。同時要當場處理：⚠️ 若砍掉內部人子指標，記得顯式宣告 `lxml`（見 §1.2 第 2 點） |
| **Q3** | 待決 **2**（來源與更新頻率） | 由 Q2 的維度集合決定要問哪些來源。**這一題有一個必須當場解掉的矛盾**：#4 為三大法人／類指數歷史／借券餘額指定的 `/rwd/` 端點，#3 判定為受爬蟲禁止條款拘束。**不解掉就會在實作時被迫臨場決定，而那是最糟的決定時機** |
| **Q4** | 待決 **5**（運算時機、快取） | 依賴 Q3 的更新頻率——若所有輸入都是日頻以下，「即時算」的唯一理由就只剩價格類指標。同時要明確劃出**哪一部分屬 #17**（排程執行器位置），本票只定分工不定位置，比照 `realtime-quotes.md` §8 對 `daily_close` 的處理方式 |
| **Q5** | 待決 **3** 剩餘（四個門檻切點、信心度要不要顯示、降級如何外顯、與分析師共識如何區分） | 必須在維度與權重確定之後才問，因為門檻是對「最終加權分數」切的。信心度那題要先讓使用者知道 `confidence = abs(final_score)`（L1843）這個事實，否則會以為在討論兩個獨立的數字 |
| **Q6** | 待決 **6**（呈現形式） | 最後。維度數（Q2）、有沒有加權貢獻可展示（Q5）、有沒有 `as_of` 分層（Q4）全部是版面的輸入。若此時判定需要原型，可比照 #11 開票 |
