## 1. 版面：側欄 + 單頁三層

```
┌────────┬──────────────────────────────────────────┐
│        │  總資產（1.75fr）        │  警示（1fr）   │
│  側欄  ├──────────────────────────────────────────┤
│ 208px  │  持股（全寬）                             │
│        ├──────────────────────────────────────────┤
│        │  最近交易（1.75fr）      │ 資產配置（1fr）│
└────────┴──────────────────────────────────────────┘
```

**為什麼是這個形狀**（依序推翻的三個候選）：

| 候選 | 為什麼不是它 |
|---|---|
| 頂部分頁 + 大 KPI 橫幅 | 分頁把警示與交易藏起來，開頁看不到今天發生什麼事 |
| 側欄 + 持股列表流 | 總資產壓成一行太弱，歷史走勢沒有位置 |
| 兩欄網格、五個小面板 | 使用者評語：**「太分散又資訊不清楚」**。面板太多太小，每個都放不下完整資訊 |

**關鍵修正**：不是「把面板搬來搬去」，而是**把面板改少改大**。從五個小面板收斂成四個，其中兩個給全寬。

**對稱靠三件事達成**（都是可驗證的規則，不是感覺）：
1. 第 1 層與第 3 層用**同一組欄寬比例 1.75 : 1**，兩層的欄縫上下對齊。
2. 全域變數 `--pad`（卡片水平內距）與 `--hd-h`（標題列高度），所有卡片吃同一組值。
3. 警示與最近交易列使用**同一種列結構**，並排時列高與對齊點才會咬合。

**手機**：側欄收成頂部橫向捲軸，所有分欄堆成單欄。使用者對此版面在手機上的評價高於在桌面上 —— 堆疊式面板在窄螢幕是優勢。

## 2. 顏色：只保留給價格方向

**紅漲綠跌，統一台股慣例，不做切換。** 美股標的（NVDA / VOO）也照台股顯示。

由此推出一條**硬性規則**：

> **介面其他任何地方都不得出現紅色或綠色** —— 按鈕、選中的分頁、側欄目前項、標籤都不行。

否則眼睛會把它讀成漲跌訊號。所有互動元素一律用**墨色**（`--ink`），沒有彩色 accent。這是被領域逼出來的設計立場，不是美感偏好。

配色詳見原型的 token 定義。類別色（資產配置）在淺色模式對比低於 3:1，因此**每一段都必須有可見的直接標籤**（不可只靠 hover）。

## 3. 連線狀態：三態，不是兩態

| 狀態 | 文案 | 語氣 | 視覺 |
|---|---|---|---|
| 即時 | `即時連線 09:00-13:30` | 正常 | 實心圓點 · 中性色 |
| **非交易時段** | `非交易時段 13:30-09:00` | **正常，不是錯誤** | 空心圓點 · **中性色** |
| **盤中斷線** | `盤中斷線 最後報價 11:42` | **異常** | 旋轉方塊 · **琥珀色** |

**為什麼非交易時段不能用警告色**：每天下午三點打開網站被一片琥珀色迎接，久了就會學會忽略它 —— 等到真的盤中斷線時也不會看了。警告色的價值來自稀有。

**兩種降級都必須同時做兩件事**，只做一件不夠：
1. 顯示橫幅說明現在看到的是什麼
2. **所有報價數字降透明度**（否則會盯著舊價格好幾分鐘沒發現）

**連線指示器絕不可使用紅綠燈** —— 綠燈=正常在此系統中會與「跌」衝突。改用**形狀 + 文字 + 琥珀色**。

文案規則：**無標點、單句、標註時段**。

台股集中市場交易時段為 **09:00–13:30**（盤後零股至 14:30）。

## 4. 即時跳動：細直條，背景永不變

價格更新時，**列的左緣閃一條 3px 直條，800ms 淡出**。背景色**永遠不動**。

被否決的做法：整列或整格的背景色殘留 —— 盯久了會累，且在密集表格中會製造整片閃爍。

**這給 [#13](https://github.com/NTUyu016/stock-analytic-platform/issues/13) 一個具體上限**：動畫 800ms，**推播節流頻率快過這個數字沒有意義** —— 眼睛還沒看完上一次閃動，下一次已經蓋上來。

實作注意：在表格中，直條用 **`td` 的 `border-left`** 實作並動畫 `border-left-color`，**不可**把儲存格改成 `display:flex` 塞子元素（會破壞表格佈局）。

## 5. 持股表欄位

| 標的 | 當日走勢 | 股數 | 成本均價 | 現價 | 漲跌 | 市值 | 未實現損益 | 報酬率 |
|---|---|---|---|---|---|---|---|---|

- **成本均價與股數**用次要墨色，與即時數字分層
- **報酬率**加粗，是視線最右的落點
- **當日走勢**併為一欄（迷你走勢圖）
- **不放「佔比」** —— 資產配置面板已在講同一件事
- 數字欄一律 `tabular-nums` 並右對齊

## 6. 交易明細：依市場拆表

分成 **台股 · 新臺幣** 與 **美股 · 美元** 兩段，**幣別在分段小標宣告一次，列上完全不標記單位**。

| 日期 | 標的 | 別 | 股數 | 成交價 | 費用 | 淨額 |
|---|---|---|---|---|---|---|

**拆表的理由不是版面，是欄位語意**：

| | 台股 | 美股（複委託） |
|---|---|---|
| 手續費 | 0.1425% × 券商折讓，最低 20 元 | **有最低收費，比例公式失效** |
| 交易稅 | 賣出證交稅 0.3%／ETF 0.1% | **沒有** |
| 股利 | 併入所得，有補充保費門檻 | **就源扣繳 30%** |

擠在同一個「費用」欄裡，那些數字是**三種不同的東西**，既不能比較也不能加總。

**顯示合併、底層分開**：`transaction` 表維持 `fee` 與 `tax` 兩個獨立欄位——兩者的費率規則與落日條款各自演進（見 [#6](../research/tw-trading-costs-taxes.md)），合併儲存會把它們綁死。

**外幣列**維持原幣別顯示（美股股價本就是美元計價），台幣等值放在 hover。若要換算，**一律採成交當日匯率，不得用今日匯率** —— 否則已經發生的歷史紀錄會每天顯示不同數字（[#9](https://github.com/NTUyu016/stock-analytic-platform/issues/9) 已定調）。

> **本項驗證了 #9 的一個決定**：因為金額存原幣別、只在顯示層換算，這個拆表需求**完全不需要動資料庫**。若當初決定入庫即換算成台幣，此需求會逼著改綱要。

## 7. 資產走勢：可拖曳選取區間

按住拖曳選取任意區間，顯示該段的 **絕對變化 + 百分比 + 方向 + 日期區間 + 交易日數**。

- 區間內用方向色描邊並填色，**區間外壓淡至 32%**
- 兩端虛線界線 + 端點圓點
- 單擊或 `Esc` 取消；切換期間（1M/3M/6M/1Y）亦清除
- 未選取時為十字準星 + 單日 tooltip；選取後準星讓位，避免兩套游標打架

⚠️ **這個互動對後端有實質需求，且是 [#16](https://github.com/NTUyu016/stock-analytic-platform/issues/16) 的直接輸入**：任意兩點之間的報酬率必須算得出來，代表**每日總資產必須逐日可得，且查詢必須夠快以支撐 60fps 的拖曳**。這使得「快照 vs 每次重算」的成本差距遠大於原先估計。

## 8. 字型

**Noto Sans TC（介面與中文） + Tahoma（數字）**

⚠️ **Noto Sans TC 不是 Windows 內建字型。** 正式站**不可假設訪客已安裝** —— 必須自行 host 字型檔並做**子集化**（完整中文字型 5–15 MB，子集化後可壓至數百 KB）。中文字型子集化是獨立的工程課題，列入實作待辦。

**字型策略必須包含 fallback 鏈的明確驗證。** 靜默 fallback 是前端最容易漏掉的問題：指定一個未安裝的字型，畫面照樣渲染、零錯誤，只是長得跟預期不同。原型內建了以 canvas 量測寬度的偵測機制，實作時應保留等效的驗證手段。

## 9. 原型過程中撞出的實作規則

這三條都是實際踩到的 bug，寫成規則避免重演：

**（a）同一標籤不得重複屬性。**
原型曾在同一個 `div` 上寫了兩個 `style`，HTML 解析器只取第一個、靜默丟棄第二個 —— `overflow-x:auto` 從未生效，表格撐破容器。lint 可攔截。

**（b）表格儲存格不得更改 `display`。**
為了塞 tick 直條而把 `td` 設成 `display:flex`，會使該儲存格脫離表格佈局、欄寬對不齊。需要在儲存格邊緣加視覺元素時用 `border`。

**（c）「建立 DOM」與「綁定事件」必須分離；重繪路徑上不得呼叫 `addEventListener`。**
原型的曲線元件把繪圖與綁定寫在同一個函式，而重繪只替換 `innerHTML`（動不到掛在外層容器上的監聽器）。拖曳時每次 `mousemove` 觸發重繪、每次重繪疊加一組監聽器 —— **監聽器數量指數成長，第二次拖曳即當機**。

> React 的宣告式渲染天然避開 (c)，但 `useEffect` 內手動綁定 listener 而依賴陣列寫錯會完全重現同一個 bug。這與 [`tech-stack.md`](./tech-stack.md) §3 提到的「持股表必須做成每列各自訂閱」是同一類風險：**React 只是讓你不容易寫錯，不是不可能寫錯。**

高頻互動（拖曳、即時 tick）的重繪應以 `requestAnimationFrame` 合併，每影格至多一次。
