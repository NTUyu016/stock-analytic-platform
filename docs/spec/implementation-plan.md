# v1 實作計畫：把規格切成工作票

> 決定於 [#18](https://github.com/NTUyu016/stock-analytic-platform/issues/18)。
> 這份文件是**票的切法與順序**，不是規格本身——每張票的「怎麼做」一律回去看 [`README.md`](./README.md) 指到的規格文件。

## 切法的三條原則

1. **每張票交付一個可驗證的東西**，不是「寫完某個檔案」。驗收條件寫在票裡。
2. **錢的計算排在最前面。** `tech-stack.md` §7 已定它是唯一嚴格 TDD 的一層，而後面所有畫面都在顯示它算出來的數字——**算錯的話，UI 做得再好也只是把錯誤畫得更清楚**。
3. **每張票標明它會撞到哪幾條「會靜默出錯」的規則。** 這些規則的共同特徵是**不報錯**，所以它們必須在票裡被點名，否則實作者不會知道自己踩到了。

## 順序的理由

```
階段 0 骨架 ──▶ 階段 1 錢的計算 ──▶ 階段 2 資料進來 ──┬──▶ 階段 3 認證與外殼 ──▶ 階段 4 儀表板
                （嚴格 TDD）                          │
                                                     ├──▶ 階段 5 即時報價 ──▶ 階段 6 警示
                                                     │
                                                     └──▶ 階段 7 排程與公司行動 ──▶ 階段 8 分析頁
                                                                                      │
                                                                                階段 9 營運
```

**階段 1 與階段 2 之間有一個刻意的順序**：先能正確地算，再去把真實資料灌進來。反過來做的話，第一次算錯時會分不清是算法錯還是資料髒——而本專案的資料源**已知有髒值**（FinMind 的 `-1.0` 缺值哨兵、yfinance 台股成交量 22.3% 的日子誤差 ≥100 倍）。

## 階段 1：錢的計算（嚴格 TDD）

> 這一階段的每一張票都**先寫測試**。`performance.md` §8A 的十一條不變量是驗收基準。

| # | 票 | 交付 | 會撞到的靜默失效 |
|---|---|---|---|
| 1.1 | **部位推導** | 給定 `transaction` 與日期 D，算出當日各標的股數 | ⚠️ **必須用 `traded_on <= D` 不等式聚合，不得 join 日曆**——實測等值 join 靜默吃掉 1.6% 的交易，**污染永久** |
| 1.2 | **成本基礎（加權平均）** | 每股取得成本，計入手續費與交易稅 | ⚠️ **現金股利不沖減成本基礎**——沖減會讓長抱高息股的成本降到零以下，報酬率分母變負、正負號整個翻過來且不報錯 |
| 1.3 | **交易成本計算** | 手續費、證交稅 | ⚠️ **元以下一律無條件捨去**（#19 用真實對帳單反推，零誤差）；**費率不得硬編碼**；ETF 0.1% vs 股票 0.3% 分流 |
| 1.4 | **四個報酬指標** | Realized P&L、Dividend Income、Unrealized P&L、Total Return | Total Return **涵蓋全部歷史含已出場部位**——只算當前持股會讓賠錢出場的部位從分母消失 |
| 1.5 | **XIRR** | 年化報酬率 + **拒絕顯示的規則** | ⚠️ 純牛頓法在三種真的會遇到的情境全部失敗（`(1+r)^n` 在 `r ≤ −1` 無實數定義）；**「猜大一點比較保險」恰好是錯的**；沒有 SUPPRESS 規則會在建倉第一週顯示 3,678% |
| 1.6 | **TWR 與基準比較** | 時間加權報酬率 + 大盤對照 | 基準**必須含息**（發行量加權股價報酬指數）——用錯成不含息指數，十年低估 47.6% |
| 1.7 | **十一條不變量測試** | `performance.md` §8A 全部落地 | 這張票的存在本身就是驗收 |

| 2.6 | **手動輸入表單** | 單筆 Transaction 輸入 | **不試算費用**（#19 定）；v1 只支援現股，當沖與信用交易一律中斷 |

## 階段 5：即時報價

| # | 票 | 交付 | 要點 |
|---|---|---|---|
| 5.1 | **fake provider** | 重播錄製的 tick 檔 | ⚠️ **dev 環境預設就是它**——Fugle 免費層 1 連線是**帳號級**，dev 接真行情會踢掉 prod |
| 5.2 | **Fugle adapter** | 訂閱 `trades` 頻道 | ⚠️ Quote 的量**必須是當日累積量**；⚠️ **退避計數必須穩定 60 秒才重置**（連上即重置會讓 flapping 時退避失效，那正是導致帳號停權的路徑）；⚠️ 超過額度**明確中斷，不優雅降級** |
| 5.3 | **`LISTEN/NOTIFY` 扇出** | worker → api | ⚠️ **listener 一律走 direct connection**；⚠️ api 只在有 SSE 連線時才持有 `LISTEN` |
| 5.4 | **SSE 與 800ms 節拍** | api → 瀏覽器 | 節流是 worker 端 conflation + 800ms 全域節拍批次送 |
| 5.5 | **連線三態指示器** | 即時／非交易時段／盤中斷線 | ⚠️ **必須反映 listener 那端，不可只監看行情源那端**——否則畫面顯示「即時連線」而價格靜止 |
| 5.6 | **開頁取價四層階梯** | api 記憶體 → 向 worker 索取全量快照 → provider REST → `daily_close` | ⚠️ 第 3 層走 **provider REST 單一標的報價**（不是 yfinance），且要讀 `capabilities.supports_symbol_quote` 不得寫死（`realtime-quotes.md` §7 更正 1） |
| 5.7 | **SSE 的 session 撤銷處理** | 登出／移出 allowlist 時立即關閉連線 + 每 60 秒兜底重查 | ⚠️ **不是可選的細節**——串流推的是即時報價，法遵要求未登入不得取得。兩層各補對方的失效模式（`auth.md` §9.1） |

## 階段 6：警示

| # | 票 | 交付 | 要點 |
|---|---|---|---|
| 6.1 | **六種具名規則類型** | `alert` + `alert_state` | ⚠️ **不做開放式運算式**——打錯欄位名求值為 null，規則永不觸發、畫面卻一直亮著 |
| 6.2 | **回歸重置去重** | hysteresis 0.5% | 非一次性、非時間冷卻 |
| 6.3 | **追蹤停損** | 峰值自建倉日起算、加碼不重置、清倉才重置 | ⚠️ **必須在除權息日按參考價比率下調**，**分割日按 `ratio` 下調**；⚠️ 峰值可重建且必須有重建路徑 |
| 6.4 | **盤中逐筆評估** | 掛在 `quote-worker` 的 conflation **之前** | ⚠️ 掛在之後等於付了 `trades` 的代價卻得到 `aggregates` 的結果，**且不報錯** |
| 6.5 | **Discord 通知** | webhook 投遞 + `notification` 紀錄 | ⚠️ **內文不得含任何金額與百分比**——報酬率是最容易漏的一格 |
| 6.6 | **規則暫停機制** | 未確認的改股數事件 → 該標的規則暫停並標示原因 | 判準是「會不會改股數」，**不加 `severity` 欄位** |

## 階段 7：排程與公司行動

| # | 票 | 交付 | 要點 |
|---|---|---|---|
| 7.1 | **排程框架** | Windows 工作排程器 → `wsl.exe … docker compose run --rm` | ⚠️ **每個任務都必須冪等且回補到最新交易日**（工作排程器的補跑機制經查證不可信任）；⚠️ 快照型端點補不回來，必須另走歷史型資料源 |
| 7.2 | **盤後批次（單一任務十個步驟）** | `daily_close`／`benchmark_series`／除權息／分割／減資／`MI_INDEX`／美股…等回補，見 `deployment.md` §4 | 四項自我斷言全過才算成功；⚠️ **步驟 ⑧（`MI_INDEX`）是唯一一個回補做不到的**，必須做斷點告警 |
| 7.3 | **Healthchecks.io 心跳** | 三個 job；`/fail` | ping URL 是機密 |
| 7.4 | **除權息偵測** | 預告表 → `pending_action` | 預告表是快照型，回補走 `TaiwanStockDividendResult` |
| 7.5 | **分割偵測與 `SPLIT`** | 偵測 → `pending_action` → 確認 → `transaction` | ⚠️ **不得用 `type` 欄位過濾**（有一列是空字串，比值 22.0 的真實分割）；⚠️ 回溯下限 2019-09-09；⚠️ 退避要認得 **HTTP 402** |
| 7.6 | **減資偵測** | 偵測到即產生 `pending_action`，**不預填比率** | ⚠️ 退還股款型的 `after/before` **不是股數比率**，自動套用會得到「看起來修好了」但錯的值 |
| 7.7 | **對帳與漏輸入偵測** | `reconciliation` 三層偵測 | ⚠️ **只比股數不比均價**（均價有定義分歧會永遠對不平）；疑似重複**只提示不自動合併** |

| # | 票 | 交付 | 要點 |
